## 1. Dataset

Dataset: IBM Transactions for Anti-Money Laundering (AML) – HI-Small subset

Source: Kaggle – IBM Transactions for Anti-Money Laundering (AML) [Dataset source on Kaggle](https://www.kaggle.com/datasets/ealtman2019/ibm-transactions-for-anti-money-laundering-aml)

The dataset is synthetic financial transaction data generated by IBM. It represents activities such as bank transfers, purchases, credit card transactions and cheques. Each transaction includes an Is Laundering indicator identifying whether it forms part of simulated money laundering activity.

For this assessment, I will use the following two files from the HI-Small subset:

## 2. Column Inventory

### HI-Small_Trans.csv

| Column | Proposed Spark data type | Description |
| --- | --- | --- |
| Timestamp | TimestampType | Date and time when the transaction occurred |
| From Bank | LongType | Identifier of the originating bank |
| Account | StringType | Originating/sender account identifier |
| To Bank | LongType | Identifier of the receiving bank |
| Account.1 | StringType | Receiving account identifier |
| Amount Received | DoubleType | Amount received by the destination account |
| Receiving Currency | StringType | Currency in which the amount was received |
| Amount Paid | DoubleType | Amount paid by the originating account |
| Payment Currency | StringType | Currency used for the payment |
| Payment Format | StringType | Transaction method, such as ACH, cheque, credit card or wire |
| Is Laundering | IntegerType | Indicator where 1 represents laundering and 0 represents a normal transaction |

The published raw transaction file contains 11 columns with two floating point amount fields, bank identifiers, account identifiers, categorical transaction attributes and the laundering indicator.

The account file can be joined to the transaction file using the bank and account identifiers.

## 3. Join Operation

The transaction and account datasets will be joined to enrich transaction records with information about the participating bank and entity.

For the sender, the join will use:

From Bank + Account → Bank ID + Account Number

The same account dataset can also be joined to the receiving side using:

To Bank + Account.1 → Bank ID + Account Number

This allows transaction behaviour to be analysed together with account/entity and bank information.

## 4. High Cardinality Column for Partitioning

The proposed high cardinality column is Account, representing the originating account.

The HI-Small dataset contains approximately 518,000 accounts, providing sufficiently high cardinality for comparing Spark hash and range partitioning strategies.

## 5. Proposed Business Case

The proposed analytical question is:

Which accounts exhibit unusually high laundering related activity over time based on their transaction behaviour, transaction value, and connections with other accounts?

## 6. Suitability for Distributed Analytics

The dataset is suitable for distributed analytics because it contains more than 5 million transaction records plus approximately 518,000 account records and requires processing across multiple related datasets.

The proposed analysis will require a combination of:

Joins between transaction and account data;

Time based transformations using Timestamp;

Multi level aggregation by bank, payment format and time period;

calculations of transaction counts, values and laundering ratios;

filtering after aggregation; and

Window based comparison or ranking against historical activity.

These operations can generate data redistribution and shuffle operations in Spark, making the dataset suitable for later investigation of partitioning, execution plans, DAG stages and query performance.
